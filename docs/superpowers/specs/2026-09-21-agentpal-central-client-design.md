# AgentPal 中心配置客户端设计

## 1. 背景与目标

AgentPal 从局域网点对点 Codex 配置同步工具，调整为中心化配置客户端。中心节点统一提供 Skills 和 MCP 配置；普通客户端连接中心节点，比较本机与中心配置差异，并由用户确认后拉取。认证配置不参与日常自动同步，而是在本机以认证档案形式管理，可手动上传到中心节点备份和下载恢复。

第一版仅支持 Codex，不支持 OpenCode 或其他 Agent 工具。

## 2. 产品边界

### 2.1 中心配置

- 中心节点运行 AgentPal Server，直接读取配置的 Codex 目录。
- 中心节点发布 `skills/` 和 `config.toml` 中的 `[mcp_servers.*]`。
- 客户端启动后连接固定中心节点，获取中心配置清单。
- 客户端比较中心配置和本机配置，展示新增、修改、本地独有和一致状态。
- 用户预览并选择变更后手动应用。
- 本机独有的 Skill 或 MCP 默认保留，只有用户明确勾选删除时才删除。

### 2.2 本地认证档案

- 认证档案以本机为主，不从中心配置清单自动下发。
- 一个认证档案包含 `auth.json` 以及与认证关联的模型和 Provider 配置。
- ChatGPT 登录档案通过导入当前有效的 Codex 登录创建。
- API Key 档案可在 AgentPal 中手动录入 Provider、Base URL、模型和 Key。
- 切换档案只更新认证相关内容，不覆盖 MCP、Projects 或其他本机配置。
- 切换前自动备份当前生效配置。

### 2.3 认证备份与恢复

- 用户可手动将本地认证档案上传到中心节点。
- 中心节点按“设备名 / 档案名”组织认证备份。
- 用户可浏览并恢复其他设备的认证备份，用于跨设备迁移。
- 恢复操作只导入为新的本地档案，不自动激活。
- 第一版运行在可信内网，不加密、不做账号鉴权。
- UI 和 README 必须明确提示认证备份包含明文敏感信息。

## 3. 运行架构

采用单程序双角色架构。`~/.agentpal/config.json` 中的 `mode` 决定程序以 Server 或 Client 角色启动。

### 3.1 Client 模式

- 启动后读取中心节点地址并自动连接。
- 中心不可达时仍进入客户端主界面，显示离线原因和重试操作。
- 本地认证档案的查看、创建和切换不依赖中心节点在线。
- 软件更新检查独立执行，不阻塞中心连接和本地操作。

### 3.2 Server 模式

- 启动后监听配置端口。
- 每次配置清单请求都从指定 Codex 目录重新计算内容和哈希，不要求管理员发布快照。
- 提供独立的认证备份存储和 API，不在配置清单中暴露认证凭据。
- 桌面界面仅显示监听状态、发布目录、Skills/MCP 数量、认证备份数量和错误信息。

## 4. 本地配置

Client 示例：

```json
{
  "mode": "client",
  "codex_dir": "~/.codex",
  "central_host": "10.10.20.11",
  "central_port": 28888,
  "device_name": "yp-mac-02"
}
```

Server 示例：

```json
{
  "mode": "server",
  "codex_dir": "~/.codex",
  "port": 28888,
  "backup_dir": "~/.agentpal/server/auth-backups",
  "device_name": "central-node"
}
```

`central_host` 和 `central_port` 是客户端连接的唯一配置来源。旧字段 `last_peer_ip` 不再参与业务逻辑。读取旧配置时可忽略未知字段，不需要维持点对点同步行为。

## 5. 认证档案模型

本地认证档案存放在：

```text
~/.agentpal/auth-profiles/<profile-id>/
  profile.json
  auth.json
  config-auth.toml
```

`profile-id` 由程序生成，不直接使用用户输入的档案名作为目录名。目录权限为 `0700`，文件权限为 `0600`。

`profile.json` 至少包含：

- 档案 ID 和显示名称
- 类型：`chatgpt` 或 `api_key`
- Provider 和模型摘要
- 创建时间、更新时间
- 来源：本机导入、手动创建或中心恢复
- 来源设备名（仅中心恢复时记录）

`auth.json` 保留 Codex 可直接使用的认证内容。`config-auth.toml` 仅保存认证相关根键和 Provider/模型配置，不保存 `mcp_servers`、`projects` 或其他本机配置。

认证相关配置的具体键集合由代码集中定义并测试。第一版至少覆盖 Codex 当前使用的模型选择、Provider 选择和 Provider 定义；不以整份 `config.toml` 作为认证档案。

## 6. 中心 API

### 6.1 健康与配置

```text
GET /health
GET /v1/config/manifest
GET /v1/config/files/skills/<relative-path>
GET /v1/config/mcp/<name>
```

配置清单包含：

- 协议版本和 AgentPal 版本
- 生成时间
- Skills 列表、文件列表、大小和 SHA-256
- MCP 名称、规范化内容和 SHA-256
- 扫描错误列表

无效或不可读取的资源不得作为可下载资源发布；错误通过清单和 Server 状态页报告。

### 6.2 认证备份

```text
GET    /v1/auth-backups
POST   /v1/auth-backups/<device>/<profile>
GET    /v1/auth-backups/<device>/<profile>
DELETE /v1/auth-backups/<device>/<profile>
```

认证备份以完整档案包上传和下载。Server 必须：

- 校验设备名、档案名和所有归档内路径，拒绝绝对路径和路径穿越。
- 限制请求体和解包后总大小。
- 使用临时目录接收并校验完整性，再原子替换目标备份。
- 同名上传必须由客户端先取得用户确认，Server 端以显式覆盖参数区分创建和覆盖。
- 列表接口只返回元数据，不返回认证内容。

## 7. 差异与应用规则

### 7.1 Skills

- 以 `skills/` 下一级目录为一个 Skill 单元。
- 根据 Skill 内文件路径和 SHA-256 判断 `new`、`changed`、`local_only` 或 `same`。
- 新增和修改项可独立选择应用。
- 本地独有项默认不选删除。
- 选中的 Skill 作为完整目录替换，替换前备份该目录。

### 7.2 MCP

- 以 `[mcp_servers.<name>]` 为一个 MCP 单元。
- 对 TOML 结构做规范化后比较，不按原始文本空白判断变化。
- 仅合并用户选中的 MCP 表。
- 本地独有 MCP 默认保留，明确选择删除后才从本机配置移除。

### 7.3 事务规则

- 所有远端文件先下载到临时目录并校验 SHA-256。
- 在修改本机配置前创建本次操作备份。
- 同一次应用中的选中变更视为一个事务。
- 下载或校验失败时不修改本机文件。
- 替换阶段失败时恢复本次操作前的文件。
- 操作结果记录应用项、删除项、备份路径和失败原因。

## 8. 认证切换规则

1. 校验档案目录、`profile.json`、`auth.json` 和 `config-auth.toml`。
2. 校验 JSON/TOML 语法及档案类型所需字段。
3. 备份当前 `~/.codex/auth.json` 和 `config.toml`。
4. 将档案中的 `auth.json` 写入临时文件并原子替换目标文件。
5. 将档案中的认证相关根键写入当前 `config.toml`，并用档案中的 Provider 配置完整替换本机同名 Provider 子树；本机缺少该 Provider 时新增。
6. 保留其他 Provider、MCP、Projects 和未归入认证范围的本机配置。
7. 任一步失败时恢复切换前文件，并保持原档案为当前生效档案。

从当前 Codex 配置导入档案时，AgentPal 复制当前认证内容和认证相关配置片段，不移动或修改当前文件。

从中心恢复时，若本地已有同名档案，默认使用“档案名（来源设备）”作为新显示名称；用户可以在导入前修改名称。恢复完成后不自动切换。

## 9. 客户端界面

客户端采用已确认的 A2 单页标签布局。

### 9.1 顶部

- 左侧显示 AgentPal。
- 右侧显示中心节点连接状态和菜单按钮。
- 菜单包含中心节点设置、Codex 目录设置、刷新和打开本地备份目录。

### 9.2 Configuration

- 作为默认标签。
- 显示中心节点地址、在线状态和刷新操作。
- 分别汇总 Skills 与 MCP 的差异数量。
- 进入预览后按状态筛选、勾选并应用。
- 离线时显示错误和重试，不显示虚假的最新状态。

### 9.3 Authentication

- 显示所有本地认证档案及当前生效档案。
- 支持导入当前 ChatGPT/API Key 配置。
- 支持手动创建 API Key 档案。
- 支持切换、重命名和删除非当前档案。
- 当前档案删除前必须先切换到其他档案。

### 9.4 Backups

- 按设备名分组显示中心认证备份。
- 支持上传本地档案、下载恢复和删除远端备份。
- 所有上传、恢复和删除操作均要求明确确认。
- 页面固定提示中心备份为可信内网中的明文敏感数据。

### 9.5 版本状态

版本信息固定在右下角，以小字显示：

- 最新版本：`v0.2.0 (latest)`
- 有新版本：`a newer version discovered · update`
- 检查失败：只显示当前版本，不阻塞其他功能。

界面在桌面和窄窗口下不得重叠。窄窗口时标签允许横向滚动或紧凑显示，版本状态不得覆盖主要按钮和内容。

## 10. Server 状态页

Server 模式不显示客户端标签，状态页包含：

- 运行状态和监听地址
- 发布的 Codex 目录
- 当前 Skills 数量和 MCP 数量
- 认证备份设备数和档案数
- 最近一次扫描时间和扫描错误
- 打开发布目录、打开备份目录和重新扫描操作

端口占用、目录不存在或目录不可读时，状态页必须显示明确错误，不显示为运行中。

## 11. 错误处理

- 中心不可达：保留本地功能，展示失败原因和重试。
- Manifest 无效或协议不兼容：禁止应用并展示版本错误。
- 资源下载或哈希校验失败：不修改本机配置。
- 认证档案缺失、语法错误或字段不完整：禁止激活。
- Server 扫描到无效 Skill/MCP：跳过对应项并报告错误。
- 同名认证备份：未明确确认时拒绝覆盖。
- 软件更新检查失败：只降级版本状态显示，不影响核心功能。

## 12. 测试与验收

### 12.1 自动化测试

- 配置文件默认值、Client/Server 模式和非法配置测试。
- Skills/MCP Manifest、规范化比较和路径安全测试。
- Skills/MCP 新增、修改、本地独有、一致和显式删除测试。
- 下载校验、备份、原子应用和失败恢复测试。
- ChatGPT 当前登录导入、API Key 档案创建和认证片段提取测试。
- 认证切换保留 MCP、Projects 和其他本机配置的测试。
- 认证备份上传、列举、覆盖、下载、删除、大小限制和路径穿越测试。
- 前端主要状态与构建测试。

### 12.2 端到端验收

- 启动一个 Server 和一个 Client 实例，Client 自动连接配置的中心节点。
- 修改 Server Codex 目录后，下一次刷新可看到对应 Skills/MCP 差异。
- 默认应用不删除本地独有项，明确选择后可以删除。
- 导入当前 ChatGPT 登录并切换到另一个 API Key 档案，再切回后均可恢复对应配置。
- 切换认证档案后 MCP 和 Projects 配置保持不变。
- 上传认证档案后可按设备名/档案名查询，并在另一设备恢复为未激活的本地档案。
- 模拟下载、校验和写入失败，确认原配置未变或已恢复。
- Go 测试、前端构建和 Wails 构建通过。
- 在桌面与窄窗口实测 A2 布局、菜单、标签、确认流程和右下角版本状态。

## 13. 非目标

第一版不包含：

- OpenCode 或其他 Agent 工具支持
- 公网部署、HTTPS、账号、权限和多租户
- 认证备份加密
- Skills/MCP 自动静默应用
- 中心配置版本历史和回滚界面
- 中心节点向客户端主动推送
- 将完整 `config.toml` 作为认证档案整体替换
